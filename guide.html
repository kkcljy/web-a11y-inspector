Practical accessibility guide

접근성 구현 가이드

실무에서 만드는 화면 요소를 검색해 필요한 HTML, ARIA, 키보드 동작과 구현 예시를 바로 확인합니다.

IMPLEMENTATION LIBRARY

실무 접근성 패턴

기본 HTML을 우선 사용하고, 커스텀 UI에는 이름·역할·상태와 키보드 동작을 함께 구현합니다.

34개 패턴
탭role, 선택 상태, 연결 관계와 방향키 이동을 함께 구현합니다.

언제 사용하는가

탭은 여러 콘텐츠 패널 중 하나를 선택해 보여주는 컴포넌트입니다. 단순 페이지 이동 링크에는 탭 역할을 사용하지 않습니다.

핵심 구현 기준

선택된 탭, 연결된 패널, 키보드 이동 상태가 항상 함께 바뀌어야 합니다.

필수 속성

  • 탭 묶음: role="tablist"와 이름
  • 각 탭: role="tab", aria-selected, aria-controls
  • 패널: role="tabpanel", aria-labelledby
  • 선택 탭만 tabindex="0", 나머지는 -1

키보드

  • Tab: 선택된 탭으로 진입하거나 탭 목록을 빠져나감
  • ← →: 이전·다음 탭으로 포커스 이동
  • Enter Space: 수동 방식일 때 탭 선택
  • Home End: 첫·마지막 탭 이동 권장
구현 예시
<div role="tablist" aria-label="상품 정보">
  <button id="tab-summary" role="tab"
    aria-selected="true" aria-controls="panel-summary">요약</button>
  <button id="tab-detail" role="tab" tabindex="-1"
    aria-selected="false" aria-controls="panel-detail">상세</button>
</div>

<div id="panel-summary" role="tabpanel"
  aria-labelledby="tab-summary" tabindex="0">...</div>
<div id="panel-detail" role="tabpanel"
  aria-labelledby="tab-detail" tabindex="0" hidden>...</div>

상태 동기화 선택이 바뀔 때 aria-selected, tabindex, 패널의 hidden을 함께 갱신합니다.

검수 체크리스트

  • 탭 목록에 의미 있는 이름이 있는가?
  • 선택된 탭만 aria-selected="true"와 tabindex="0"인가?
  • 각 탭의 aria-controls가 실제 패널 id와 연결되는가?
  • 방향키, Home, End 이동 후 포커스와 선택 상태가 어긋나지 않는가?
아코디언제목 버튼과 콘텐츠 영역을 연결하고 펼침 상태를 전달합니다.

가장 간단한 구현은 기본 HTML인 details와 summary입니다. 커스텀 디자인이 필요할 때만 버튼 패턴을 사용합니다.

필수 속성

  • 제목 안에는 실제 button을 사용
  • 버튼에 aria-expanded="false|true"
  • aria-controls로 펼쳐질 영역의 id 연결
  • 패널은 버튼의 id를 aria-labelledby로 연결 가능

키보드

  • Enter Space: 펼치기·접기
  • Tab Shift+Tab: 일반 순서대로 이동
  • 방향키 이동은 선택 사항이며 필수 동작이 아님
  • 접힌 패널 안 요소는 Tab 순서에서 제외
커스텀 구현 예시
<h3>
  <button id="faq-button" type="button"
    aria-expanded="false" aria-controls="faq-panel">
    환불 규정
  </button>
</h3>
<div id="faq-panel" role="region"
  aria-labelledby="faq-button" hidden>...</div>

상태 동기화 열 때 aria-expanded="true"와 hidden=false, 닫을 때 반대로 변경합니다. 패널이 많으면 모든 패널에 role="region"을 붙이지 않습니다.

모달과 레이어제목, 내부 포커스, 바깥 조작 차단과 닫은 뒤 복귀가 필요합니다.

언제 사용하는가

가능하면 기본 dialog 요소와 showModal()을 사용합니다. 단순히 화면만 어둡게 만들고 포커스를 가두지 않으면 모달이 아닙니다.

핵심 구현 기준

모달이 열리면 조작 범위가 모달 내부로 제한되고, 닫은 뒤에는 열었던 요소로 포커스가 돌아와야 합니다.

필수 속성

  • dialog 또는 role="dialog"
  • 모달이면 aria-modal="true"
  • aria-labelledby로 보이는 제목 연결
  • 아이콘 닫기 버튼에는 aria-label="닫기"

포커스와 키보드

  • 열 때 제목 또는 첫 조작 요소로 포커스 이동
  • Tab이 모달 내부에서만 순환
  • Escape로 닫기
  • 닫은 뒤 모달을 열었던 버튼으로 포커스 복귀
구현 예시
<dialog id="delete-dialog" aria-labelledby="delete-title">
  <h2 id="delete-title" tabindex="-1">항목을 삭제할까요?</h2>
  <p>삭제한 항목은 복구할 수 없습니다.</p>
  <button type="button">취소</button>
  <button type="button">삭제</button>
  <button type="button" aria-label="닫기">×</button>
</dialog>

주의 긴 문서형 모달은 전체 내용을 aria-describedby로 묶지 말고 제목에 먼저 포커스를 두어 구조대로 읽게 합니다.

검수 체크리스트

  • 모달 제목이 화면에 보이고 aria-labelledby로 연결되는가?
  • 열릴 때 포커스가 모달 안으로 이동하는가?
  • Tab과 Shift+Tab이 모달 내부에서 순환하는가?
  • Escape 또는 닫기 버튼으로 닫을 수 있는가?
  • 닫은 뒤 포커스가 모달을 연 버튼으로 돌아오는가?
버튼과 링크실행은 버튼, 페이지 이동은 링크로 만들고 목적이 드러나는 이름을 제공합니다.

언제 사용하는가

클릭 가능한 div를 만들지 않습니다. 화면에 보이는 글자가 있다면 접근 가능한 이름에도 같은 문구가 포함되어야 합니다.

핵심 구현 기준

화면 안에서 기능을 실행하면 버튼, 다른 위치나 문서로 이동하면 링크를 사용합니다.

구분 기준

  • 저장, 열기, 삭제, 상태 변경: button
  • 다른 주소나 위치로 이동: a href
  • 아이콘만 있는 버튼: 동작을 설명하는 이름 제공

확인 항목

  • 이름만 읽어도 대상과 결과를 예상 가능
  • 같은 이름의 버튼이 반복되면 대상을 포함
  • 비활성 버튼은 이유를 주변 문구로 안내
구현 예시
<button type="button">가입 정보 저장</button>
<a href="/products/insurance">보험 상품 보기</a>
<button type="button" aria-label="검색창 닫기">
  <svg aria-hidden="true">...</svg>
</button>

주의 아이콘만 있는 버튼은 시각적 모양이 아니라 실행 결과를 이름으로 제공합니다. 같은 문구가 반복되면 대상 정보를 함께 넣습니다.

검수 체크리스트

  • 버튼과 링크를 기능 기준에 맞게 구분했는가?
  • 아이콘 버튼에 동작을 설명하는 이름이 있는가?
  • 같은 이름의 반복 버튼이 있을 때 대상을 구분할 수 있는가?
  • 키보드로 이동하고 실행할 수 있는가?
입력 항목명, 도움말과 오류보이는 label을 연결하고 설명과 오류를 입력칸에 함께 전달합니다.

placeholder는 입력 예시일 뿐 항목명을 대신하지 않습니다. 오류가 생기면 어떤 항목을 어떻게 고쳐야 하는지 구체적으로 안내합니다.

필수 연결

  • label for와 입력칸 id 일치
  • 도움말·오류 id를 aria-describedby에 연결
  • 오류가 있을 때만 aria-invalid="true"
  • 필수 여부는 화면과 코드에서 모두 제공

오류 처리

  • “입력 오류” 대신 원인과 수정 방법 안내
  • 제출 후 첫 오류 또는 오류 요약으로 포커스 이동
  • 오류 색상과 함께 문구 또는 아이콘 제공
오류 상태 예시
<label for="email">이메일 (필수)</label>
<input id="email" type="email" required
  aria-invalid="true"
  aria-describedby="email-help email-error">
<p id="email-help">업무용 이메일을 입력하세요.</p>
<p id="email-error">example@company.com 형식으로 입력하세요.</p>
체크박스와 라디오 그룹기본 입력 요소를 사용하고 그룹 질문은 fieldset과 legend로 제공합니다.

디자인 때문에 기본 입력을 숨기더라도 포커스와 상태 전달이 유지되어야 합니다. display:none으로 제거한 입력은 키보드로 접근할 수 없습니다.

체크박스

  • 여러 항목을 독립적으로 선택
  • Space로 선택 상태 변경
  • 부분 선택 커스텀 상태는 aria-checked="mixed"

라디오

  • 한 그룹에서 하나만 선택
  • 같은 name으로 그룹 구성
  • 방향키로 그룹 안 선택 이동
라디오 그룹 예시
<fieldset>
  <legend>알림 수신 방법</legend>
  <label><input type="radio" name="notice" value="email"> 이메일</label>
  <label><input type="radio" name="notice" value="sms"> 문자</label>
</fieldset>
선택창과 자동완성기본 select를 우선 사용하고 커스텀 콤보박스는 전체 키보드 동작을 구현합니다.

단순 선택은 기본 select가 가장 안전합니다. 검색 가능한 커스텀 선택창이 꼭 필요할 때만 콤보박스 패턴을 구현합니다.

콤보박스 속성

  • 입력 요소에 role="combobox"
  • aria-expanded로 목록 표시 상태 전달
  • aria-controls로 목록 id 연결
  • 목록은 role="listbox", 항목은 role="option"

키보드

  • ↓ ↑: 목록 항목 이동
  • Enter: 현재 항목 선택
  • Escape: 목록 닫기
  • 입력 중 일반 편집 키 동작을 막지 않음
기본 선택창 예시
<label for="category">문의 분야</label>
<select id="category">
  <option value="">선택하세요</option>
  <option value="product">상품 문의</option>
  <option value="payment">결제 문의</option>
</select>
이미지 대체 텍스트이미지가 전달하는 정보와 기능에 따라 alt를 다르게 작성합니다.

정보 이미지

  • 파일명이 아니라 이미지가 전달하는 내용을 작성
  • 주변 문구와 같은 설명을 반복하지 않음
  • 차트는 핵심 요약과 상세 데이터를 함께 제공

장식·기능 이미지

  • 장식 이미지는 alt=""
  • 링크나 버튼 안 이미지는 보이는 모양보다 기능을 설명
  • CSS 배경에 중요한 정보를 넣지 않음
구현 예시
<img src="chart.png" alt="2026년 가입자 수가 전년보다 18% 증가">
<img src="divider.png" alt="">
<a href="/home"><img src="logo.svg" alt="A11Y Inspector 홈"></a>
글자와 UI 명도 대비글자 크기와 굵기를 판정한 뒤 실제 배경색과의 대비를 확인합니다.

글자 기준

  • 일반 글자: 최소 4.5:1
  • 24px 이상 일반 글자: 최소 3:1
  • 18.66px 이상 굵은 글자: 최소 3:1
  • 로고와 비활성 UI의 글자는 예외

글자 외 기준

  • 입력창 경계와 선택 상태: 최소 3:1
  • 정보를 전달하는 아이콘과 그래픽: 최소 3:1
  • 오류·선택 상태를 색상만으로 구분하지 않음

확인 방법 반투명 색상, 이미지 배경, 그라데이션 위 글자는 최종 합성된 실제 픽셀 색을 기준으로 가장 대비가 낮은 지점을 확인합니다.

데이터 표caption으로 표의 목적을 설명하고 th와 scope로 데이터 관계를 연결합니다.

레이아웃을 맞추는 용도로 표를 사용하지 않습니다. 데이터 표는 표만 읽어도 무엇을 비교하는지 이해할 수 있어야 합니다.

필수 구조

  • caption: 표 제목 또는 목적
  • 열 머리글: th scope="col"
  • 행 머리글: th scope="row"
  • 복잡한 병합표는 가능하면 단순한 여러 표로 분리

정렬 기능

  • 정렬 버튼은 머리글 안에 배치
  • 현재 정렬 열에 aria-sort 제공
  • 화살표 모양만으로 정렬 상태를 전달하지 않음
구현 예시
<table>
  <caption>월별 보험료 비교</caption>
  <thead><tr>
    <th scope="col">상품</th>
    <th scope="col">월 보험료</th>
  </tr></thead>
  <tbody><tr>
    <th scope="row">기본형</th>
    <td>32,000원</td>
  </tr></tbody>
</table>
제목과 페이지 영역내용 관계에 맞는 제목 단계와 header, nav, main, footer 영역을 사용합니다.

제목

  • 페이지 대표 제목을 명확히 제공
  • 내용 계층에 따라 h1 → h2 → h3 순서 사용
  • 글자 크기 때문에 제목 단계를 선택하지 않음

페이지 영역

  • 핵심 본문은 하나의 main에 포함
  • 여러 nav에는 서로 다른 이름 제공
  • 반복 메뉴가 길면 본문 바로가기 제공
구현 예시
<header>...</header>
<nav aria-label="주 메뉴">...</nav>
<main id="main-content">
  <h1>보험 상품 비교</h1>
  <section><h2>보장 내용</h2>...</section>
</main>
<footer>...</footer>
키보드 포커스모든 기능에 이동할 수 있고 현재 위치가 항상 분명하게 보여야 합니다.

이동 순서

  • DOM의 의미 있는 순서와 화면 순서를 일치
  • tabindex 양수 값 사용 금지
  • 숨겨진 콘텐츠의 조작 요소는 Tab 순서에서 제외
  • 고정 영역이 포커스를 완전히 가리지 않게 함

표시

  • 기본 outline을 이유 없이 제거하지 않음
  • 배경과 분명히 구분되는 포커스 스타일 제공
  • 마우스 hover와 포커스 상태를 모두 설계
포커스 스타일 예시
:focus-visible {
  outline: 3px solid #0068d9;
  outline-offset: 3px;
}
상태 메시지와 알림저장 완료, 검색 결과, 오류처럼 바뀐 내용을 포커스 이동 없이 알립니다.

role="status"

  • 저장 완료, 검색 결과 수처럼 급하지 않은 변경
  • 사용자의 현재 작업을 끊지 않고 안내
  • aria-live="polite"와 같은 성격

role="alert"

  • 즉시 알아야 하는 오류나 경고에 제한적으로 사용
  • 반복 변경되는 영역 전체에 사용하지 않음
  • 알림만으로 입력칸 연결을 대신하지 않음
구현 예시
<p role="status">검색 결과 12건을 불러왔습니다.</p>
<p id="payment-error" role="alert">
  결제가 완료되지 않았습니다. 카드 정보를 확인하세요.
</p>

구현 팁 라이브 영역은 가능하면 페이지에 미리 두고, 작업 결과가 생겼을 때 내부 문구를 갱신합니다.

메뉴 버튼과 드롭다운버튼의 펼침 상태와 메뉴 항목의 방향키 이동, 닫기 동작을 구현합니다.

단순 사이트 링크 목록은 일반 탐색 영역으로 만들고, 애플리케이션 명령 목록일 때 메뉴 패턴을 사용합니다.

필수 속성

  • 여는 요소는 실제 button
  • aria-haspopup="menu"
  • aria-expanded로 열림 상태 전달
  • aria-controls로 메뉴 id 연결 가능

키보드

  • Enter Space: 메뉴 열기
  • ↑ ↓: 메뉴 항목 이동
  • Home End: 첫·마지막 항목
  • Escape: 닫고 메뉴 버튼으로 복귀
구현 예시
<button id="more-button" type="button"
  aria-haspopup="menu" aria-expanded="false"
  aria-controls="more-menu">더보기</button>
<ul id="more-menu" role="menu" aria-labelledby="more-button" hidden>
  <li role="none"><button role="menuitem" tabindex="-1">복사</button></li>
  <li role="none"><button role="menuitem" tabindex="-1">삭제</button></li>
</ul>
툴팁과 도움말마우스 hover뿐 아니라 키보드 포커스에서도 같은 설명을 확인할 수 있게 합니다.

표시 조건

  • 대상에 hover 또는 포커스가 오면 표시
  • 대상과 툴팁 위에 포인터가 있는 동안 유지
  • Escape로 닫을 수 있게 함
  • 툴팁 자체에는 조작 요소를 넣지 않음

연결

  • 툴팁에 role="tooltip"
  • 대상에 aria-describedby로 툴팁 id 연결
  • 아이콘 버튼의 이름은 툴팁이 아니라 별도 제공
구현 예시
<button type="button" aria-label="도움말"
  aria-describedby="password-tip">?</button>
<span id="password-tip" role="tooltip" hidden>
  영문, 숫자, 특수문자를 조합하세요.
</span>

주의 반드시 읽어야 하는 안내는 툴팁에 숨기지 말고 화면에 항상 보이는 문구로 제공합니다.

캐러셀과 슬라이드이전·다음·정지 버튼을 제공하고 보이지 않는 슬라이드를 읽지 않게 처리합니다.

필수 조작

  • 이전·다음 버튼에 구체적인 이름 제공
  • 자동 전환 시 정지·재생 버튼 제공
  • 포커스 진입과 hover 시 자동 전환 정지
  • 사용자가 다시 시작하기 전 자동 재생 금지

구조

  • 전체에 이름이 있는 region 또는 group
  • aria-roledescription="carousel" 사용 가능
  • 현재 보이지 않는 슬라이드는 hidden 처리
  • 현재 위치를 “2 / 5”처럼 전달
구현 예시
<section aria-label="주요 소식" aria-roledescription="carousel">
  <button type="button">자동 전환 정지</button>
  <button type="button" aria-label="이전 소식">‹</button>
  <div role="group" aria-roledescription="slide" aria-label="1 / 3">...</div>
  <button type="button" aria-label="다음 소식">›</button>
</section>

화면에서만 숨김

  • 시각적으로 숨기는 전용 클래스 사용
  • 버튼 이름, 표 설명처럼 보조기기에 필요한 문구에 제한
  • 중요한 안내 전체를 화면에서 숨기지 않음
시각적으로 숨기는 예시
.sr-only {
  position: absolute;
  width: 1px;
  height: 1px;
  overflow: hidden;
  clip-path: inset(50%);
  white-space: nowrap;
}
차트와 데이터 시각화색과 그래픽을 보지 못해도 핵심 결론과 정확한 데이터를 확인할 수 있게 합니다.

대체 정보

  • 차트 앞뒤에 핵심 결론을 문장으로 제공
  • 정확한 값은 표 또는 다운로드 가능한 데이터로 제공
  • 범례를 색상뿐 아니라 이름·무늬·선 모양으로 구분

그래픽

  • SVG에 이름과 설명 연결
  • Canvas만 사용하면 별도의 접근 가능한 콘텐츠 제공
  • 툴팁 정보는 키보드 포커스로도 확인 가능
SVG 이름 예시
<svg role="img" aria-labelledby="chart-title chart-desc">
  <title id="chart-title">월별 가입자 수</title>
  <desc id="chart-desc">1월 120명에서 6월 210명으로 증가</desc>
  ...
</svg>
무한 스크롤과 더보기새 콘텐츠가 추가된 사실과 위치를 알리고 끝까지 키보드로 접근할 수 있게 합니다.

권장 방식

  • 자동 로드만 사용하지 말고 “더 보기” 버튼 제공
  • 추가된 항목 수를 상태 메시지로 전달
  • 버튼 포커스를 유지해 연속 조작 가능

확인 항목

  • 새 항목 때문에 현재 읽던 위치가 이동하지 않음
  • 페이지 하단 메뉴와 기능에 도달 가능
  • 로딩 실패 시 다시 시도 버튼과 오류 안내 제공
구현 예시
<ul id="result-list">...</ul>
<button type="button" aria-controls="result-list">결과 더 보기</button>
<p role="status">결과 20건이 추가되었습니다.</p>
